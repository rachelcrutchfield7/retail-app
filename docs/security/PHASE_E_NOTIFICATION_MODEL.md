# Phase E Notification Model

Date: 2026-07-19

## Principle

Clients no longer create arbitrary notifications. Notification content, recipient, route, data, and deduplication keys are generated by trusted database workflows.

## Internal Helper

`private.create_notification_for_event` validates:

- active recipient
- title length
- body length
- route length
- deduplication key length
- stored notification preferences

It inserts idempotently using `(user_id, dedupe_key)` and is not executable by ordinary client roles.

## Source Matrix

| Source | Recipient | Creator | Dedupe Key |
| --- | --- | --- | --- |
| Message | Other conversation participant | `send_message` RPC | `message:<message_id>` |
| Favorite | Listing seller | Favorite insert trigger | `favorite:<favorite_id>` |
| Linked transaction completion | Linked buyer | `complete_listing_transaction` RPC | `transaction:<transaction_id>:completed:<recipient_id>` |
| Review | Derived reviewee | `create_transaction_review` RPC | `review:<review_id>:<recipient_id>` |
| Saved search | Saved-search owner | `create_saved_search_notifications_for_listing` trigger | `saved-search:<saved_search_id>:<listing_id>` |

## User Notification Actions

Users can:

- read only their own non-deleted notifications
- mark one owned notification read
- mark all owned notifications read
- soft-delete one owned notification

Users cannot directly update notification ownership, content, type, route, data, dedupe key, or creation timestamp.

## Preferences

Notification preferences are read and updated only through user-owned RPCs. If no row exists, database defaults are:

- in-app messages, favorites, reviews, marketplace updates, and system: enabled
- push messages, favorites, reviews, and marketplace updates: disabled

Trusted notification creation reads stored preferences; the in-memory client preference cache is not authoritative.

## Device Tokens

Device tokens are registered and removed only through controlled RPCs. A token belongs to one current account. Registering the same token for a different account transfers ownership to the current authenticated user. Device token rows are not exposed through normal application reads.
